权威配置为 `config/songs.yaml`，下表只是常用入口，不是完整别名列表。

## 使用与匹配规则

- 可以直接发送歌名或关键词，也可以发送 `点歌 历史`、`點歌：历史`、`song 历史`、`dg历史`。
- `历史`、`歴史`、`歷史`、`今日が歴史に残るなら`、`如果今天将被铭刻于历史` 均精确匹配 song_026。
- 全角/半角、大小写、空格、常见标点、复制时附带的零宽字符不影响匹配；日文长音符仍保留。
- 日文全名、中文显示名、已收录译名、编号和人工关键词先精确匹配。两个字的关键词必须明确收录，不把所有两个字都交给模糊匹配。
- 未精确命中时，至少三个字符才尝试歌名片段或相似度匹配；相似度阈值仍为 90。
- 模糊候选按不同歌曲汇总；多首过线则拒绝猜测，并在内部结果/日志里给出候选歌名和编号。目前程序不向直播间发送这种回复弹幕。
- 不再因一句聊天中包含某个别名就直接匹配。纯数字和 song 编号只接受已有编号，不模糊猜编号。
- `RETURNER / 觉醒` 默认原版；`电音` 是 Electric Returner；`电音R / Type R` 是 Type R。
- `风大` 默认白龙原版；`风大翻唱 / 风大cover` 是法兰秀秀翻唱。仅输入 `return` 会报告三个版本有歧义。
- 角色名、团名、系列名不适合普遍绑定一首歌；保留已有明确的角色曲别名，不把“纯子”“爱”“佐贺”绑定成任意曲目。
- 冷却时间、重复歌曲检查、队列大小及随机播放逻辑均未改变。

## 维护与验证

新增译名优先记录原投稿链接或实际字幕证据；没有来源的直觉关键词应按人工入口说明。
同一标准化别名不可配置到两首歌，加载时会报冲突；相近版本请添加版本限定词。
不能通过降低全局阈值或放开任意短词来代替补充关键词。

在项目根目录运行离线验证，不需要凭据、不连直播间，也不会向正式队列塞测试歌曲：

```bash
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/python -m compileall -q bili_songbot tests
git diff --check
```

匹配器与曲库在进程启动时加载；仅编辑 YAML 不会更新已经运行的进程。
部署前验证直播状态，按运维规则仅重启受影响的 songbot，并验证健康端点及 RTMP 发送字节继续增长。
不要为了别名更新重启 keeper、启用备用黑屏推流器或重写推流凭据。
