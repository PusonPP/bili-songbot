# 第二轮歌词审校与音源核验

日期：2026-11-10 UTC / 2026-11-11 Asia/Shanghai。

## 验收边界

本轮核对全部 42 份用户提供的原文/译文，并对全部原始音频实际解码。
这不是只检查文件名、时长或工程测试，但也**不是逐句听校**。
用户允许先验证子代理能否听音频，再决定分批。实际给一个代理提供了 23.87 秒
Drive-in Tori 音频作盲测，禁止查文件、调用 ASR 或猜歌词；代理明确反馈无法听到
附件音频。该代理已关闭，没有启动后续听校批次，听校通过数仍为零。

独立 ASR 在本机 CPU 上运行，不上传到外部语音服务，也不提供原歌词提示。
它只能辅助发现错版、缺段和疑似偏移。重复副歌、背景和声、长音和拟声段都会导致
识别或词级定位错误；即便置信度较高，也不能直接签署字幕精确时间验收。

## 音源核验

`scripts/audit_lyric_audio.py` 同时检查实际解码、FLAC STREAMINFO 样本数、PCM MD5
及解码错误。FFmpeg 返回 0 并不代表没有坏帧。依据为
[FLAC 格式规范](https://www.rfc-editor.org/rfc/rfc9639.html)的 STREAMINFO 定义。

- 40 首原件完整解码且校验通过。
- song_028《佐賀事変》有解码错误提示，但全部 10,640,448 个 PCM 样本帧与原头部
  MD5 完全一致。另用 libsndfile 完整解码并生成本地诊断用 FLAC，重新检查无错误且
  PCM MD5 相同。只将这份无损副本用于离线识别，**没有替换直播音频或用户原件**。
- song_030 标称 13,957,944 帧，实际仅 13,800,960 帧，缺 156,984 帧，即约
  3.559728 秒；PCM MD5 不符，另一解码器也报失步。损坏位置不应推断成“只缺尾巴”。
  ZIP 成员 CRC 有效、SHA256 与解出的 FLAC 一致，说明重新解压不会恢复。
  当前和五月备份视频也只有约 312.947 秒音频，未找到完整替代来源。
  **用户已要求暂缓，等待补交音源**。未补静音、未修改标称长度、未继续修复此曲。

新建底片现在会先通过完整性检查，并用 FFmpeg `-xerror` 拒绝解码错误。
这只影响之后的离线构建，不重新构建或中断正在播放的媒体。

另外将 41 首附件音源与当前曲库实际播放文件做波形抽查，用户暂缓的 030 不参与。
每首在约 10%、50%、90% 位置各取 5 秒，8 kHz 单声道、前后各约 5 秒搜索窗口，
归一化互相关峰值全部位于零偏移，相关系数范围 0.988657 至 0.999850。
这 123 个窗口支持“抽查位置未引入音源偏移”，不是整曲每个采样点无误、
不是 B 站接收端音画同步验证，更不是声乐与字幕逐句对应的证明。

## 不重启部署

新文字位于 `media/lyrics/20261110-v3-textfix/`，只改 9 首、12 个显示段；
新旧 ASS 的所有事件起止毫秒逐项相等，原音频、底片与曲库时长不变。
离线实际渲染了九首的修订帧。六首无轴修订只保存文本，未替换播放。

先备份旧 ASS，再在相关歌曲未播放时原子替换旧路径为新 ASS 的兼容软链接；
曲库同时记录新路径，以供下一次正常启动。现有渲染器每段重新解析路径，
因此已经运行的进程也能读取新文字，不需重启。旧 ASS 保存在同目录带时间戳的备份。
这次明确例外地将旧发布路径变为链接，未声称旧发布目录所有字节保持不变。

部署清单和回退目标记录于
`runtime/lyrics-audit-20261110/textfix-deployed.json`。没有改 keeper、systemd 或任何凭证。
